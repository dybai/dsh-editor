# @dybai/dsh-editor

**@dybai/dsh-editor** 让 DeepSeek Harness（DSH）工作区里的文本文件可以直接在对话旁就地编辑、保存（`Ctrl+S`）。DSH 原本只能只读预览工作区文件，想改就得跳出对话换外部工具；本插件补上「改文件」这一环：打开即编辑、保存写回磁盘，外部修改和误删都有保护。

它同时是可扩展的**编辑器框架**：工具栏、状态栏、编辑模式、键位等全部开放给第三方插件，契约见 [docs/contracts.md](docs/contracts.md)。

## 安装

前置要求：DSH 引擎 `dsh >= 0.2.1-rc.5`；安装完成后浏览器 **Ctrl+F5** 刷新生效。

**插件市场（推荐）**：

1. DSH 设置 → 插件 → 安装官方可选 bundle `@deepseek-ai/dsh-experimental-plugin-market-bundle`（实验性插件市场，提供 Discover 标签页）；
2. 在市场设置里**添加索引源**：`https://raw.githubusercontent.com/dybai/dsh-editor/main/market-index.json`；
3. Discover 里找到「DSH 编辑器」→ 安装 → 刷新页面。

**npm 直接安装**：`plugin_manager` → `install_bundle`，spec 填 `@dybai/dsh-editor@0.4.0`（新版本号以 npm 页面或市场索引为准）。

**本地开发**：`install_bundle` 的目标为本仓库目录的绝对路径；开发循环见 [docs/deploy.zh-CN.md](docs/deploy.zh-CN.md) §3。

## 框架概述

三层架构：

- **集成层**（任意第三方插件，零依赖）：注册座位 occupant、消费 `dshEditor` 服务、注册编辑模式、经导航契约打开文件——只依赖"名字"，不 require 本包；
- **框架层**（本包）：唯一状态与编排所有者——tab 状态机与保存队列（乐观并发 + 冲突横幅）、模式解析与挂载、工具栏/状态栏 chrome 与座位渲染、草稿/视图状态持久化、Host RPC 桥；
- **模式层**（React 组件）：内容视图。内置 `plain-text`（fallback）与 `code-highlight`（语法高亮，0.17.0；1.0.0 起渲染面为 vendored CodeMirror 6 内容面，见下文「语法高亮」）；第三方以 `extension`/`builtin` 带注册排序接入，切换模式保草稿。

完整契约见 **[docs/contracts.md](docs/contracts.md)**（座位 owner props、句柄切片、模式描述符、Host RPC、导航契约、持久化、演进规则）。

## 快速开始

**安装**：见上方[「安装」](#安装)章节（插件市场 / npm 包 / 本地目录三条渠道）。

**打开**：

- 交互：文件预览工具栏的铅笔"编辑"按钮（只对文本文件渲染，原只读预览保留不动）；
- 程序化：`ctx.get('dshEditor').open(address, { line })` 或 `ctx.sidebarRight.openResource(address, { kind: 'editor', params: { file: { line } } })`——带 `line` 时打开后定位到该行。

**保存与键位**：

- `Ctrl+S` 保存前台编辑器；`Ctrl+Shift+S` 保存当前会话全部未保存的编辑器；`Ctrl+D` 删除光标行/选区触及行；`Ctrl+G` 打开跳转到行面板。这四条是**框架自管键位**：编辑器根元素拦截 keydown 并自行 `preventDefault`（对任何组合有效，不受 DSH web 快捷键白名单限制），编辑器之外浏览器默认行为照旧；
- 键位是全局用户偏好：编辑器状态栏右端的**齿轮**打开设置中心的「快捷键」分区，逐动作「录制」新组合（允许任何组合，含浏览器保留键）或「恢复默认」，持久化到 Host 存储、所有已挂载编辑器立即生效（详见 [docs/contracts.md](docs/contracts.md) §6）；
- 磁盘文件被外部修改时出现冲突横幅：**重新加载并丢弃本地修改** 或 **仍要保存（覆盖磁盘）**；
- 编辑中途崩溃/刷新后重新打开同一文件，未保存草稿自动恢复（磁盘文件也变过时先出冲突横幅，绝不静默覆盖）。

**外部修改与删除检测**（0.3.0）：

- 打开中的文件被外部修改时，编辑器顶部弹出浅黄悬浮条：**是[重新加载]**（丢弃本地修改读入磁盘）/ **否[放弃更新]**（保留本地修改，保存时冲突横幅兜底）/ **否[不再询问]**（本页签内不再询问，保存时仍兜底）；
- 文件被外部删除时，页签文件名标红并画上删除线，悬浮条询问是否关闭页签；选择保留可继续编辑，**Ctrl+S 保存即重建文件**（成功后红标消失）。外部同路径重建会被识别并清除红标；
- 删除后**原样保存不需要先修改内容**：干净草稿下保存按钮/Ctrl+S 首次触发只布防确认（按钮变「确认重建」警示色），再次触发才执行重建；任何编辑或外部状态变化自动解除布防；
- 检测走宿主 `workspaceFiles/changes` 推送流（实时、零轮询），流不可用时自动降级为切换回页面/窗口聚焦时检查；
- 干净文件自动重载可在状态栏右端齿轮打开的**设置中心**（「行为」分区）中开启（默认关闭 = 一律询问），持久化到 Host 存储。

**活动行高亮**（0.4.0）：

- 编辑区以光标所在行的上下细边线标记当前行（VS Code 风格，不填背景——为将来的语法高亮留出颜色空间），随光标移动、内容编辑与滚动实时跟随；多行选区时边线跟随光标端（拖拽释放所在行），选区本身由浏览器原生选区样式呈现，不逐行描边；
- 设置中心「外观」分区新增「高亮光标所在行」开关（默认开，全局持久化，对所有已挂载编辑器立即生效）；
- 第三方模式可在描述符声明 `activeLine: true` 接入同一契约：经组件 prop `highlightActiveLine` 接收偏好、以快照 `selection.lineStart`/`lineEnd` 为高亮范围自行绘制（见 [docs/contracts.md](docs/contracts.md) §5.1 / §5.5）。

**行号列**（0.5.0）：

- 编辑区内容左侧显示行号列：宽度随最大行号位数自适应（跨 100/1000 行等进位时自动加宽），随滚动、编辑、行导航实时同步；
- 设置中心「外观」分区新增「显示行号」开关（默认开，全局持久化，对所有已挂载编辑器立即生效）。开关只控制数字显隐：分界竖线与左侧预留带常驻，切换不会移动正文位置；
- 无描述符声明字段：`showLineNumbers` 偏好经组件 prop 直接送达到每个挂载的模式组件，第三方模式可自行接入（绘制行号列）或安全忽略（见 [docs/contracts.md](docs/contracts.md) §5.1 / §5.5）。

**跳转到行**（0.6.0）：

- `Ctrl+G` 打开跳转面板（状态栏 `Ln/Col` 指示器正上方的小输入面板），输入框默认置空并自动聚焦：输入行号后回车或点「跳转」即把光标定位到**目标行行首**（焦点随之回到编辑区），面板关闭；
- 输入自动收敛到 `1–总行数`（越界取最近的有效行）；空/非数字输入给出内联提示、不跳转；文件仍在加载时也允许输入，加载完成后延迟落点（`failed` 相位禁用跳转）；
- 面板关闭路径：跳转成功 / `Esc` / 点击面板外 / 页签转为不可见；
- `Ctrl+G` 与其余三条一样可在设置中心「快捷键」分区「录制」改键；**旧版本已自定义过键位的用户升级后键位原样保留**，新增的跳转键按 `Ctrl+G → Ctrl+Shift+G → Ctrl+Alt+G` 候选链自动补位（默认键被占用时顺延），迁移只发生在读取侧、不改写已存储数据；
- 热键链路（派发/退避/解析/跳转/迁移）带 `[dsh-editor]` 前缀的 `console.debug` 日志，浏览器控制台勾选 verbose 即可定位每一步的状态。

**光标与视口位置恢复**（0.8.0）：

- 关闭页签、刷新页面或切换回同一文件时，自动恢复上次的选区（光标或多行选区）与可视区域（垂直 + 水平滚动），有记录时不再从文件顶部开始；
- 位置按“工作区根 + 文件路径”记忆：同一工作区跨会话共享（工作区根未知时按会话隔离），不同工作区的同名文件互不干扰；localStorage 明文保存（仅本机，LRU 200 条 / 90 天）；
- 显式导航优先：带 `line` 打开、`Ctrl+G` 跳转不会被旧位置覆盖；
- 文件内容变短或行被删除时，位置收敛到当前文本的有效行；第三方编辑模式可经可选 props `initialScroll` / `onScrollChange` 接入滚动恢复（不接入也会恢复机器选区；模式需按契约镜像机器选区并让编辑区取得焦点，光标才可见）。

**滚动越过最后一行**（0.9.0）：

- 编辑区内容末尾之后保留可滚动空白：底部空白区域可以滚到屏幕上方，滚到尽头时只剩最后一行贴在视口顶部（行号列与高亮条同步贴顶）；短文件（含单行）同样生效；
- 设置中心「外观」分区新增「滚动越过最后一行」开关（默认开，全局持久化，对所有已挂载编辑器立即生效），关闭后恢复“最后一行贴底”的旧行为；
- 无描述符声明字段：`scrollBeyondLastLine` 偏好经组件 prop 直接送达到每个挂载的模式组件，管理自身滚动容器的第三方模式可自行接入或安全忽略（见 [docs/contracts.md](docs/contracts.md) §5.1 / §5.5）。

**自动换行**（0.10.0）：

- `md` / `markdown` / `mdx` 文件默认折行，`txt`、`js` 等其余扩展名默认不折行（VS Code 同构）；折行发生在**词边界**，只有超长单词/URL 才会被硬折（`overflow-wrap: break-word` 兜底）；
- 设置中心「换行」分区新增「自动换行」开关：显示的是**全局显式值**（未设置时按钮显示「关」，并注明「未设置时按扩展名默认（md 系开）」）；点击写入全局显式值，对所有文件立即生效。显式设置一旦存在，它对 md 与 txt 一视同仁地覆盖内置默认——需要「只改 md 不改 txt」时用同分区的「本类型换行」覆盖（0.11.0，见下节）；
- 折行下三种定位全部保真：行号列逐行与逻辑行对位、活动行高亮只覆盖**光标所在的那个视觉行**（VS Code 风格：光标停在折行边界时算上一视觉行的行尾，多行选区本身仍由浏览器原生绘制）、`Ctrl+G` 与 End 键按视觉行精确落点；关闭换行立即回到 0.9.0 的水平不折行观感（滚动位置由浏览器按新范围钳制，无报错）；
- 拖拽窗格宽度时行号先用近似估算顶上（不消失，数值可能短暂不准），松手约 200ms 后全量重测校准；数千行的大文件同样先出近似行号、测量推进中界面保持可交互，完成后自动对齐；
- 折行纯属显示层：文件里一个字符都不会被改写，保存回磁盘的仍是原始长行；
- 无描述符声明字段：`wordWrap` 偏好经组件 prop 直接送达到每个挂载的模式组件，管理自身折行的第三方模式可据此对齐用户意图，不支持的模式忽略即可（见 [docs/contracts.md](docs/contracts.md) §5.1 / §5.5）。

**设置中心与按类型换行**（0.11.0）：

- 状态栏右端的**齿轮**是唯一设置入口：打开一个**应用级单例模态**设置中心（半透明遮罩 + 居中面板，左分区菜单 / 右内容滚动区），`Esc`、点击遮罩、右上角关闭按钮三种退出方式，关闭后焦点归还齿轮；单例意味着多个页签/会话共用同一个对话框，打开它的页签关掉后对话框仍可继续使用（换行分区只保留打开时的文件上下文用于展示）；
- 四个分区：**外观**（高亮光标所在行 / 显示行号 / 滚动越过最后一行——行为与 0.10.0 的设置浮窗等价，切换对所有已挂载编辑器实时生效）、**行为**（干净文件自动重载）、**换行**（全局开关 + 本类型覆盖）、**快捷键**（原键位浮窗整体迁入：四动作录制 / 恢复默认 / 冲突与浏览器保留组合提示原样保留；录制中按 `Esc` 只取消录制、不关闭对话框）；
- 按类型换行：换行分区多出「本类型换行」一行，按打开文件的扩展名显示 `*.md（main.md）` 这样的上下文，点击在 **跟随全局 → 强制开 → 强制关** 三态间循环并同时显示该类型的有效值；覆盖优先于全局显式设置（三层链：命中的 per-glob 覆盖 > 全局显式 > 内置扩展名默认），所以「md 折行、txt 不折行」这类按类型设定现在可以直接做；无扩展名的文件该行禁用（只有「跟随全局」可表达）；
- 跨窗口实时生效：任一偏好写入成功后经 `BroadcastChannel` 广播（不可用时降级 localStorage 通知），其他窗口收到后立即重读全部偏好缓存并生效；窗口重新聚焦 / 页面恢复可见时再兜底刷新一次。双窗口同时改同一项由 Host 侧 CAS 拒绝后写者（提示后重读，不静默覆盖）；
- 覆盖面与边界：外观 / 行为 / 换行作用于所有已挂载编辑器与之后新开的文件。第三方模式仍经组件 prop `wordWrap` 收到**当前文件的三层链最终值**，不感知层级（见 [docs/contracts.md](docs/contracts.md) §5.5 / §8）；设置中心本身是纯 UI 演进，不新增第三方契约面（第三方设置分区座位本期不开放）。

**空白字符显示**（0.12.0）：

- 设置中心「外观」分区新增「空白字符显示」分组的三行开关：**显示空格**（空格字符渲染为浅色间隔号 `·`）、**显示制表符**（制表符渲染为浅色箭头 `→` 并补位到下一制表停位，4 列默认）、**显示换行符**（每个行断的行尾渲染浅色回车符 `↵`，**每个真实行断都显示**——`a\nb\n` 显示 `a↵\nb↵`，文件末尾回车立即反馈，不再有「补画一次」的滞后）。三行相互独立、默认全关，全局持久化，对所有已挂载编辑器立即生效，并经既有跨窗口同步（`BroadcastChannel`，不可用时降级 localStorage 通知）实时生效到其他窗口；
- 字形为浅色：取标签色约 25% 不透明度、随主题自适应，垫在正文之下不干扰阅读；被选中文本内的字形由原生选区背景覆盖（v1 接受的取舍）；
- 不折行与折行两种模式下对齐保真：不折行时字形层按行高窗口算术定位（可视行 ±2 行缓冲），折行时与框架折行机器共享同一套逐视觉行文本切片——`↵` 只出现在逻辑行的**最后一个视觉行**行尾，字形进宽由 CSS 强制为一字宽、行 span 不自行折行，字形与正文逐行对位；
- 纯显示层：字形只画在独立的覆盖层里，文件内容一个字符都不会被改写，保存回磁盘的仍是原始文本；三个开关全关时字形层不挂载、零成本；
- 第三方模式志愿接入：`showWhitespace` prop（`{ spaces, tabs, newlines }` 实时布尔对象）直接送达到每个挂载的模式组件，无描述符声明字段，自行绘制空白字形的模式可据此对齐用户意图，不支持的模式安全忽略（见 [docs/contracts.md](docs/contracts.md) §5.1 / §5.5）。

**Tab 缩进**（0.13.0）：

- 内置纯文本模式编辑区**固定占用 Tab / Shift+Tab**（缩进 / 反缩进，不可录制、不受键位自定义影响），且**四相位（加载中 / 就绪 / 保存中 / 失败）一律吞键，焦点永不逃逸**编辑区——再也不会按一下 Tab 把焦点丢到窗格外；
- 三种选区形态全覆盖：**折叠光标**插入一个缩进单位、**单行选区**被缩进单位替换、**跨行选区**整块缩进（每个触及行行首插入单位）；Shift+Tab 反缩进逐行删去一个前导制表符或最多一个宽度单位的前导空格，所有触及行都无可删时吞键不写回；
- 缩进模式「**自动探测**」按文件本身判定：扫描前 200 个非空行，任一行以制表符开头立即判定制表符缩进；否则统计 1–16 列的前导空格宽度、出现最频者胜（并列取更小宽度）；文件无任何信号时回退到设置的缩进宽度（默认 4）；
- 设置中心新增「**缩进**」分区：**模式**（自动探测 / 制表符 / 空格）与**宽度**（2 / 4 / 8）两个分段选择器，写入全局设置、对所有已挂载编辑器立即生效，并经既有跨窗口同步（`BroadcastChannel`，不可用时降级 localStorage 通知）实时生效到其他窗口；宽度行仅在「空格」模式下可用，其余模式禁用并注明「自动探测无信号时也用它作回退宽度」；
- **撤销保真**：写入走 `document.execCommand('insertText')` 主路径，保留浏览器**原生撤销栈**——一次缩进（含整块跨行缩进）Ctrl+Z 一步回退；execCommand 不可用或反缩进拼接形状不安全时回退机器内容写命令（与删行同模式：功能可用，但该步不进原生撤销）；
- **键位录制器**扩展保留组合规则：裸 Tab 与 Shift+Tab 拒绝录制（编辑器缩进固定占用），快捷键分区的保留组合提示同步更新（见 [docs/contracts.md](docs/contracts.md) §5.1 / §6 / §8）。

**行尾保留**（0.13.0）：

- 打开 CRLF / CR 文件后编辑保存，**行尾不再被改写成 LF**：读入时探测文件行尾（混合行尾按主导行尾归一），保存时把编辑内容还原为该行尾写盘（VS Code 同构）；此前 CRLF 文件经「打开→保存」会被静默转换为 LF；
- 编辑器内部与显示层恒为 LF（textarea 硬约束，`\r` 无法在文本区呈现）——空白字符显示的 `↵` 按 LF 断行绘制，与行尾保留互不影响；新建文件默认 LF；
- 无新增契约面：`writeFile` 的 wire 形状不变，`content` 携带文件原生行尾（见 [docs/contracts.md](docs/contracts.md) §1 / §8）；
- 显示层同步区分：换行符显示开启时，CRLF 文件的每个行断画 **␍+↵ 双记号**（与文件字节一对一）、CR 文件画 **␍**、LF 维持 **↵**；混合行尾按主导行尾显示（与保存归一一致）；机器公共 state 新增 additive 字段 `eol`（第三方模式可经 controller 订阅读取，见 [docs/contracts.md](docs/contracts.md) §4.2）。**CM6 面注记（1.0.0）**：`code-highlight` 的 CM6 内容面上 `␍` 记号暂不渲染（`↵` 照常）——机内文档恒为 LF、CM6 字形层按文档文本推导字形所致；纯文本面照旧画 `␍+↵`。已接受的 1.0.0 显示缺口（纯显示、零编辑影响），见下方「手动矩阵」。

**竖线标尺**（0.14.0）：

- VS Code 同构的编辑器竖线参考线：在正文第 N 个字符格的右缘画一条全高 1px 细线，线色取边框色、随明暗主题自适应，垫在正文之下绘制——正文、选区与行号带都在其上，不遮挡任何内容；
- 默认关闭，位置默认第 80 列。设置中心「外观」分区新增「标尺」分组：**显示竖线标尺**开关 + **标尺位置（列）**数字输入行，全局持久化，对所有已挂载编辑器立即生效，并经既有跨窗口同步（`BroadcastChannel`，不可用时降级 localStorage 通知）实时生效到其他窗口；
- **几何列语义**：列按字符数计（Tab、全角字符都只算一列，不按视觉展宽折算），竖线位置为纯几何偏移（行号带宽度 + 列号个 `ch`）——行号 99→100 进位使行号带变宽后，竖线仍与字符格右缘逐位对位；
- **折行与水平滚动**：折行模式下竖线恒为固定列，不随视觉行断行移动；不折行时随内容水平滚动平移，经过行号带之下不外露；
- 底色承载与空白字符层同一规则：活动行高亮、空白字形层都不在时由标尺层承载基底背景色，多层叠加时恒有且仅有一层垫底，不露底也不重复上色；关闭开关后标尺层整个卸载、零成本；
- 第三方模式志愿接入：`ruler` prop（`{ enabled, column }` 实时对象）直接送达到每个挂载的模式组件，无描述符声明字段，自行绘制标尺的模式可据此定位竖线，不支持的模式安全忽略（见 [docs/contracts.md](docs/contracts.md) §5.1 / §5.5）；
- 设置中心交互与收敛规则：位置输入在**失焦或回车**后提交（点步进箭头即等价提交）；输入为空或不是数字时回退显示当前生效值、不写盘；越界或带小数的输入按 1–999 整数收敛（四舍五入取整、越界收敛到边界，如 `80.5→81`、`1000→999`）后提交；位置可与开关独立设置——先定列号、后开标尺。

**页签文件类型图标**（0.15.0）：

- 编辑器页签标题在文件名前渲染一枚 16px 文件类型图标：图标经运行时引用取自宿主共享组件（`@deepseek-ai/dsh-client-ui-primitives` 的 `FileTypeIcon` + `classifyFileType`），与 DSH 文件预览页签**同一图标集**——同一文件在两处图标一致；零复制、零许可负担；
- 宿主运行时缺失该共享模块（旧版 dsh）时自动降级为纯文件名，不报错；外部删除红标、键位、设置等一切既有行为不受影响；
- 无开关、无设置项（与预览页签一致是产品语义）；图标纯装饰，不进任何契约面。

**页签编辑徽标**（0.16.0）：

- 编辑器页签的类型图标左下角叠加一枚 12px 白色圆盘徽标（内含 10px 灰色编辑图形）：**预览页签无徽盘、编辑器页签有**——同一文件两种页签一眼可辨；类型图标本体零改动，文件类型辨识不受损；
- 徽盘与类型图标同门禁：宿主运行时缺失共享模块时一并降级为纯文件名；外部删除红标、键位、设置等一切既有行为不受影响；明暗两主题同款白盘（经用户在 100% 缩放即最不利渲染档位下目验接受，更高缩放渲染只更清晰）；
- 徽盘内图形为自有派生资产：改自宿主 MIT 许可的 `edit-outline` 图形（加粗描边以适配 10px 尺寸），出处在此声明；无开关、无设置项，不进任何契约面。

**语法高亮**（0.17.0）：

- 常见代码/配置文件打开即语法高亮：内置 `code-highlight` 模式（builtin 优先级——高于 plain-text fallback、低于第三方 extension 模式，模式菜单可「本次用 plain-text 打开」或「设为默认」随时切回纯文本，无需新增开关）。1.0.0 起渲染面为 **vendored CodeMirror 6 内容面**（CM6 本体同为懒加载 chunk）：shiki 引擎（TextMate 语法 + JS 正则引擎）产出 token 流，经 Decoration 在 CM6 文档视图上输出，token 颜色引用宿主主题的 `--shiki-*` CSS 变量——亮/暗主题自动跟随，插件零主题代码；行级增量分词只从首个变更行起重分词（语法状态收敛即提前停止），且只为视口附近行渲染 Decoration，编辑与滚动保持流畅；
- 语言覆盖共 **32 种**，按文件扩展名匹配（单一事实源 `src/highlight/languages.js`，完整语言表见 spec §4）：`javascript` / `typescript` / `json` 三条**预热语法**打进主 bundle，打开即高亮零等待；其余语言按亲和分四个**懒加载 chunk**，首次用到组内任一语言整组加载——`web`（html、css、scss、less、vue、svelte）、`script`（shell、python、ruby、php、perl、lua、powershell）、`system`（c、cpp、csharp、go、java、kotlin、rust、swift）、`data`（yaml、toml、ini、xml、sql、markdown、diff、dotenv）；
- 降级行为——高亮永远只是视觉增强，绝不影响编辑/保存/草稿：未知扩展名（`Makefile`、`Dockerfile` 等无后缀文件名亦同，无内容嗅探）→ 纯文本渲染；单行超 1000 字符该行不分词；chunk 加载失败、引擎初始化失败或分词异常 → 回落纯渲染（失败组本会话负缓存、不重试风暴，日志走诊断通道，不弹错）；CM6 本体 chunk 加载失败（如文件缺失/被拦截）→ 整页降级为纯文本可编辑（degraded 恒置、本会话不重试，无重试风暴）；
- 分级分词（0.18.0）——**≤ 256 KiB**：打开即全量分词（即时全彩）；**256 KiB – 8 MiB**：渐进后台着色——先以纯文本可编辑打开，rAF 背景帧逐批分词，颜色随滚动/阅读逐步填充完成（期间编辑、保存、增量分词照常，不受影响）；**> 8 MiB 或 > 20 万行**：该页签引擎停用，体验等同纯文本；
- 渲染面演进（1.0.0）：0.17.0–0.20.0 的「透明 ink textarea 叠加背景层」取舍已随 CM6 内容面退役——正文即真字形渲染，**粗体/斜体/下划线按语言语义以真字重呈现**（不再为 token 步进不变式牺牲字重），**输入法组合输入恢复正常**（中文/日文等 IME 组合单次提交、无重复字符）；旧版「高亮激活期间正文文字透明、输入法组合文本仅下划线可见」的限制随之消除；
- 验证清单见 .superpowers/specs/2026-11-25-code-highlight-design.md §12。

**匹配高亮**（0.18.0）：

- 光标停在一个词上或选中一段文本时，文档中的匹配内容以背景色标出（对齐 VS Code 双层行为）：**词层**高亮光标处完整词的所有全词出现（区分大小写），**选区层**高亮选区字面文本的其它出现（不区分大小写，与当前选区重叠的位置除外），两层可同时点亮，plain-text 与 code-highlight 两个内置模式同时获得，第三方模式经组件 prop `matchHighlight` 志愿接入；折行、Tab 展宽与中文行下逐可视行精确对齐，编辑/滚动/折行切换/主题切换/输入法组合输入下保持稳定，高亮只是视觉增强、绝不影响编辑/保存/草稿。

| 座位 ×3 | `ctx.slots.inject('dsh-editor.actions' / 'dsh-editor.status' / 'dsh-editor.unavailable', …)` | 向工具栏/状态栏/失败空态放 occupant，owner props 含 `address`/`path`/`sessionId`（status 另有渲染时刻 `snapshot`） |

## 已知限制（v0.2 非目标）

以下为契约已预留、v1 **不实现**的能力：

- `contentKind: 'raw'` 路径与自定义传输（二进制/分页内容由模式自带读写）；
- hex 查看、编辑区浮层座位（find/minimap）等 builtin 富模式及细粒度扩展面——其中语法高亮已于 0.17.0 以内置 `code-highlight` 模式落地（1.0.0 起其渲染面为 vendored CodeMirror 6 内容面，见上文）；
- `fs` 字节写 facet（当前仅整文件 UTF-8 文本写，≤4 MB，文本格式白名单）；
- 模式关联管理设置页（关联目前仅经模式菜单"设为默认/恢复默认"管理）。

自动换行（0.10.0 引入，0.11.0 起为三层解析）的明确非目标（记录在案，去向已定）：

- **4 MiB 编辑上限不随换行调整**：`MAX_EDIT_CHARS` / `MAX_CONTENT_CHARS` 是 textarea 预算，本版不动；与「大文件模式」一并解决；
- **无渐进分块测量（A2）**：本版只有挂载时的一轮有界初始化分块，不维护"部分精确"的常驻状态；与「大文件模式」一并解决（届时只换测量模块内部，查询接口与组件触点不变）；
- **按类型覆盖只支持 `*.<ext>` 形态**：换行覆盖按扩展名后缀匹配（单段 `*` + 点 + 1–16 位小写字母/数字），不支持任意 minimatch glob（如 `src/**`、`*.test.*`）与按工作区/目录的作用域；任意 glob 随未来的覆盖管理 UI 一起 additive；
- **无 `Alt+Z` 式临时开关**：不能只对当前页签临时切换换行且不持久化；等真实需求出现再 additive。

另有：只能编辑会话工作区内的文本文件；编辑器以独立 tab 打开，不替换当前预览 tab；键位录制会拒绝浏览器生命周期保留组合（Ctrl/⌘+W/T/N/Q、Ctrl+Tab 等）并给出提示——页面层无法可靠拦截这类浏览器默认行为。

### 手动矩阵（待用户实页验收）

CM6 内容面迁移的实页验收清单——自动化守卫之外，以下各条须在真实 DSH 页面人工逐条验收：

- CM6 焦点内四组合（`Ctrl+S` / `Ctrl+Shift+S` / `Ctrl+D` / `Ctrl+G`）全部可达根拦截；
- 中文/日文 IME 组合输入单次提交、无重复字符；
- 粗体/斜体/下划线真字重渲染（C++/Rust/TS 各采样一段）；
- 折行下行号/活动行/匹配高亮对齐；
- 大文件（256KiB–8MiB）渐进着色随进度推进、>8MiB 纯文本停用；
- chunk 失败降级：临时改名 `client.editor-cm6.js` 后开代码文件 → 纯文本可编辑、无重试风暴；
- 标尺 1–999 列收敛与折行恒定列；
- 空白三开关（`·`/`→`/`↵`，含制表停位补位与行尾记号）；
- 模式切换往返（CM6→纯文本→CM6）草稿/脏标/版本无损；
- CRLF 文件空白显示：`␍` 记号在 CM6 面不渲染（已接受的 1.0.0 缺口，见上文「行尾保留」注记与 spec）；
- scrollBeyondLastLine 末行滚至视口顶、无回弹；
- 纯文本 tab 冒烟：match/whitespace/ruler/wrap/active-line/gutter/selection 与 0.20.0 一致。
